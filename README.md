## افرا چیست؟

افرا یک پنل مدیریت پروکسی است که **کاملاً روی زیرساخت Cloudflare** اجرا می‌شود. برخلاف پنل‌های سنتی
که به یک سرور مجازی (VPS) وابسته‌اند، افرا از Workers برای پردازش، D1 برای داده، KV برای کش،
R2 برای پشتیبان و Durable Objects برای هماهنگی استفاده می‌کند.

افرا مستقل و از صفر نوشته شده است و هیچ کدی از پروژه‌های دیگر در آن کپی نشده.

**تمام رابط کاربری، پیام‌های خطا، اعلان‌ها و پیام‌های ربات تلگرام فارسی هستند.**

## معماری

```
                         ┌──────────────────────────┐
        کلاینت‌ها  ─────▶ │   Cloudflare Edge Layer  │
                         │     (afra-edge Worker)   │
                         │  · تحویل اشتراک /sub/:t  │
                         │  · endpoint پروکسی VLESS │
                         └────────────┬─────────────┘
                                      │ D1 + KV مشترک
   ┌──────────────────────────────────▼──────────────────────────────┐
   │              Control Plane (afra-control-plane Worker)          │
   │  · رابط کاربری React (Workers Static Assets)                    │
   │  · REST API نسخه‌دار /api/v1                                     │
   │  · Cron Triggers (سلامت، نگهداشت، پشتیبان)                      │
   │  · لایهٔ یکپارچه‌سازی Cloudflare API                             │
   └──────┬──────────┬───────────┬────────────┬───────────┬──────────┘
          │          │           │            │           │
       ┌──▼──┐   ┌───▼───┐   ┌───▼───┐   ┌────▼─────┐  ┌──▼──────────┐
       │ D1  │   │  KV   │   │  R2   │   │ Durable  │  │  Queues     │
       │داده │   │ کش    │   │پشتیبان│   │ Objects  │  │ (اختیاری)   │
       └─────┘   └───────┘   └───────┘   └──────────┘  └─────────────┘
```

### تفکیک مسئولیت‌ها

| لایه | مسئولیت |
|---|---|
| **Control Plane** | مدیریت، کاربران، اشتراک‌ها، تنظیمات، تحلیل‌ها، انتشار endpoint |
| **Edge Worker** | تحویل اشتراک و endpoint پروکسی روی لبه |
| **D1** | منبع حقیقت پایدار (۲۵ جدول با مهاجرت نسخه‌دار) |
| **KV** | کش نشست، کش تنظیمات، allowlist کاربران روی لبه |
| **R2** | پشتیبان‌های رمزنگاری‌شده |
| **Durable Objects** | `RateLimiterDO` (پنجرهٔ لغزان نرخ) · `HealthCoordinatorDO` (بررسی سلامت single-flight) |
| **Cron Triggers** | بررسی سلامت (۵ دقیقه) · نگهداشت ساعتی · پاک‌سازی و پشتیبان روزانه |

### چرا این معماری؟

- **بدون سرور دائمی**: هیچ VPS ای برای پنل لازم نیست؛ هزینه و نگهداری کمتر.
- **نزدیک به کاربر**: تحویل اشتراک و endpointها از شبکهٔ لبهٔ Cloudflare.
- **منبع حقیقت مشترک**: هر دو Worker به یک D1 و KV متصل‌اند؛ تغییر در پنل فوراً روی لبه اعمال می‌شود.
- **قابل‌توسعه**: افزودن پروتکل، فرمت اشتراک، DNS provider یا کانال اعلان جدید = یک فایل جدید + ثبت در رجیستری.

## قابلیت‌ها

<details open>
<summary><b>مدیریت و امنیت</b></summary>

- احراز هویت مدیر با هش **PBKDF2-HMAC-SHA512** (۲۱۰٬۰۰۰ تکرار، مقدار پیشنهادی OWASP)
- ورود دومرحله‌ای **TOTP** (اختیاری) + کد بازیابی یک‌بارمصرف
- نشست امن با کوکی `HttpOnly; Secure; SameSite=Strict` و کش KV
- محافظت **CSRF** (double-submit با راز سمت سرور)
- محدودسازی نرخ با Durable Object + محافظت brute-force روی ورود
- **RBAC** با ۲۵ مجوز دانه‌ای و سه نقش (مدیر ارشد، مدیر، فقط خواندنی)
- گزارش رویدادها (audit log) برای همهٔ اقدام‌های مدیریتی
- رمزنگاری اسرار در دیتابیس با **AES-256-GCM**
- هدرهای امنیتی: CSP، `X-Frame-Options: DENY`، `nosniff`، Referrer-Policy، Permissions-Policy
- اعتبارسنجی کامل سمت سرور با **Zod** روی همهٔ ورودی‌ها

</details>

<details open>
<summary><b>کاربران و اشتراک‌ها</b></summary>

- کاربران با سهمیهٔ کل و روزانه، انقضا، برچسب، توضیحات و سرورهای اختصاصی
- عملیات: ایجاد، ویرایش، فعال/غیرفعال، تمدید، بازنشانی حجم، چرخش اعتبارنامه، چرخش توکن، حذف
- جستجو، فیلتر وضعیت، صفحه‌بندی و **عملیات گروهی**
- اشتراک با فرمت‌های **Auto / Base64 / Clash (Mihomo)** و تشخیص خودکار از User-Agent
- کد QR، کپی لینک، هدر استاندارد `subscription-userinfo`
- لغو و بازتولید اشتراک؛ توکن ۲۵۶ بیتی که هرگز در لاگ ثبت نمی‌شود

</details>

<details open>
<summary><b>سرورها، پروتکل‌ها و شبکه</b></summary>

- Nodeها در دو نوع: **endpoint مدیریت‌شدهٔ Cloudflare** یا **سرور بیرونی**
- adapterهای پروتکل: **VLESS، Trojan، Shadowsocks** با interface مشترک
- Transportها: **WebSocket، gRPC، XHTTP** با TLS 1.2/1.3، SNI، ALPN و fingerprint
- **بررسی سلامت واقعی** با باز کردن اتصال TCP/TLS (نه شبیه‌سازی) و وضعیت‌های سالم/کند/خارج از دسترس
- **توازن بار**: اولویت‌محور، وزنی، کم‌ترین تأخیر، سلامت‌محور + failover خودکار
- **موتور مسیریابی**: domain، suffix، keyword، IP، CIDR (IPv4/IPv6)، GeoIP، GeoSite + ورودی/خروجی JSON
- **موتور DNS**: DNS استاندارد، DoH، DoT با بررسی سلامت و سرور پشتیبان
- **فیلترینگ دامنه**: فهرست سفید/سیاه/تبلیغات/ردیاب — بدون فهرست از پیش تحمیل‌شده
- **زنجیرهٔ پروکسی** با ویرایشگر بصری و اعتبارسنجی پیش از ذخیره
- **بک‌اند** و **WARP** به‌صورت کاملاً اختیاری با بررسی سلامت
- قالب نام‌گذاری Node: `{FLAG} {COUNTRY} {CITY} {NAME} {PROTOCOL} {INDEX} {DATE}`

</details>

<details open>
<summary><b>یکپارچه‌سازی Cloudflare</b></summary>

- **انتشار واقعی Worker** از داخل پنل: افرا کد endpoint را تولید و از طریق Cloudflare API منتشر می‌کند
- Worker منتشرشده به همان **D1 و KV** پنل bind می‌شود (احراز هویت و شمارش ترافیک روی دادهٔ واقعی)
- مدیریت DNS record، Worker route، دامنهٔ اختصاصی و مشاهدهٔ منابع حساب (Workers/D1/KV/R2)
- هم‌گام‌سازی allowlist کاربران با کش لبه
- توکن با کمترین مجوز، رمزنگاری‌شده at rest، فقط سمت سرور

</details>

<details open>
<summary><b>ربات تلگرام و اعلان‌ها</b></summary>

- ربات اختیاری با پیام‌های فارسی و allowlist مدیران (نقش مدیر / فقط خواندنی)
- دستورها: `/users` `/user` `/usage` `/sub` `/adduser` `/extend` `/quota` `/enable` `/disable` `/health`
- اعتبارسنجی راز webhook تلگرام + محدودسازی نرخ + ثبت رویداد هر دستور
- موتور اعلان: خرابی/بازیابی سرور، انقضای کاربر، هشدار حجم، رویداد امنیتی — در پنل و تلگرام

</details>

<details open>
<summary><b>رابط کاربری</b></summary>

- **فارسی و RTL کامل** با فونت Vazirmatn و ارقام فارسی
- **تاریخ شمسی (جلالی)** با گزینهٔ میلادی
- مقادیر فنی (UUID، IP، دامنه، URL) همیشه چپ‌به‌راست
- **موبایل‌محور**: جدول در دسکتاپ، کارت در موبایل — بدون اسکرول افقی اجباری
- پوستهٔ روشن / تیره / سیستم
- حالت‌های بارگذاری، خطا، خالی و تأیید برای همهٔ عملیات
- دسترس‌پذیری: ناوبری با کیلد، ARIA، کنتراست خوانا، نشانگر focus
- **جادوگر راه‌اندازی هشت‌مرحله‌ای** فارسی در نخستین اجرا

</details>

## نصب و راه‌اندازی

### ۱. دریافت کد و نصب وابستگی‌ها

```bash
git clone https://github.com/mb1384/afra-panel.git
cd afra-panel
npm install
```

### ۲. ورود به Cloudflare

```bash
npx wrangler login
```

### ۳. ساخت منابع Cloudflare

```bash
# دیتابیس D1
npx wrangler d1 create afra-db

# فضای KV
npx wrangler kv namespace create AFRA_KV

# سطل R2 برای پشتیبان (اختیاری اما توصیه‌شده)
npx wrangler r2 bucket create afra-backups
```

### ۴. جای‌گذاری شناسه‌ها

شناسه‌های خروجی دستورهای بالا را در دو فایل زیر جایگزین مقادیر `REPLACE_ME_...` کنید:

- `apps/control-plane/wrangler.jsonc`
- `apps/edge/wrangler.jsonc`

> ⚠️ هر دو Worker باید به **همان** D1 و KV اشاره کنند.

### ۵. تعیین کلید رمزنگاری (اجباری)

```bash
# تولید کلید تصادفی
openssl rand -base64 48

cd apps/control-plane
npx wrangler secret put AFRA_SECRET_KEY
```

این کلید برای رمزنگاری اسرار (توکن تلگرام، توکن Cloudflare، راز بک‌اند، کلید TOTP) استفاده می‌شود.
**اگر آن را گم کنید، اسرار ذخیره‌شده قابل بازیابی نخواهند بود.**

### ۶. اعمال مهاجرت‌های دیتابیس

```bash
# محلی
npm run db:migrate:local

# روی Cloudflare
npm run db:migrate:remote
```

### ۷. ساخت و استقرار

```bash
npm run build      # ساخت رابط کاربری در apps/control-plane/public
npm run deploy     # استقرار هر دو Worker
```

### ۸. راه‌اندازی اولیه

آدرس Worker پنل را در مرورگر باز کنید. جادوگر هشت‌مرحله‌ای فارسی اجرا می‌شود:

۱. خوش‌آمدید ۲. ایجاد مدیر ارشد ۳. منطقهٔ زمانی ۴. دیتابیس ۵. تلگرام (اختیاری)
۶. سرور اول (اختیاری) ۷. بررسی امنیت ۸. پایان + **کد بازیابی**

> 🔑 کد بازیابی فقط یک‌بار نمایش داده می‌شود. آن را در جای امنی ذخیره کنید.

## توسعهٔ محلی

سه ترمینال:

```bash
# ۱) API + Worker پنل (پورت 8787)
npm run dev:api

# ۲) رابط کاربری با Hot Reload (پورت 5173، پروکسی به 8787)
npm run dev:web

# ۳) Worker لبه (پورت 8788) — اختیاری
npm run dev:edge
```

برای اسرار در حالت محلی، فایل `apps/control-plane/.dev.vars` بسازید (این فایل در `.gitignore` است):

```ini
AFRA_SECRET_KEY=یک-کلید-تصادفی-طولانی
CLOUDFLARE_ACCOUNT_ID=
CLOUDFLARE_API_TOKEN=
TELEGRAM_BOT_TOKEN=
TELEGRAM_WEBHOOK_SECRET=
```

Miniflare همهٔ سرویس‌ها (D1، KV، R2، Durable Objects) را به‌صورت محلی شبیه‌سازی می‌کند؛ نیازی به
اتصال به Cloudflare برای توسعه نیست.

## استقرار روی Cloudflare

### محیط‌های جداگانه

سه محیط از پیش تعریف شده است و منابع آن‌ها هرگز با هم تداخل نمی‌کنند:

| محیط | دستور | منابع |
|---|---|---|
| development | `npm run deploy` | `afra-db`, `afra-backups` |
| staging | `npm run deploy:staging -w @afra/control-plane` | `afra-db-staging`, `afra-backups-staging` |
| production | `npm run deploy:production -w @afra/control-plane` | `afra-db-production`, `afra-backups-production` |

برای هر محیط، منابع مجزا بسازید و مهاجرت‌ها را جداگانه اعمال کنید:

```bash
npm run db:migrate:staging -w @afra/control-plane
npm run db:migrate:production -w @afra/control-plane
```

### انتشار endpoint پروکسی از داخل پنل

۱. توکن Cloudflare را تنظیم کنید (بخش «متغیرهای محیطی»).
۲. در پنل به **Cloudflare → انتشار endpoint** بروید.
۳. یک Node از نوع «Cloudflare» با پروتکل VLESS و transport WebSocket انتخاب کنید.
۴. نام Worker را وارد کنید؛ افرا کد را تولید، منتشر و دامنهٔ `workers.dev` را فعال می‌کند.
۵. در صورت تمایل، Zone و دامنهٔ اختصاصی را انتخاب کنید تا route ساخته شود.

Worker منتشرشده به D1 و KV پنل bind می‌شود، UUID کاربران را اعتبارسنجی می‌کند و مصرف ترافیک
را در دیتابیس ثبت می‌نماید.

### endpoint های سلامت

| مسیر | توضیح |
|---|---|
| `GET /health` | زنده بودن سرویس |
| `GET /ready` | آمادگی + بررسی اتصال D1 و KV |

## متغیرهای محیطی

نمونهٔ کامل در فایل [`.env.example`](.env.example). روش توصیه‌شده برای اسرار، `wrangler secret put` است.

| نام | اجباری | توضیح |
|---|---|---|
| `AFRA_SECRET_KEY` | ✅ | کلید AES-256-GCM برای رمزنگاری اسرار (حداقل ۲۴ نویسه) |
| `CLOUDFLARE_ACCOUNT_ID` | — | برای مدیریت خودکار منابع Cloudflare |
| `CLOUDFLARE_API_TOKEN` | — | توکن **scoped** (نه Global API Key) |
| `TELEGRAM_BOT_TOKEN` | — | توکن ربات تلگرام |
| `TELEGRAM_WEBHOOK_SECRET` | — | راز اعتبارسنجی webhook تلگرام |
| `AFRA_PANEL_URL` | — | برای CORS در حالت توسعه |
| `AFRA_EDGE_URL` | — | دامنهٔ Worker لبه برای ساخت لینک اشتراک |

### مجوزهای لازم توکن Cloudflare

```
Account · Workers Scripts        · Edit
Account · Workers KV Storage     · Edit
Account · D1                     · Edit
Account · Workers R2 Storage     · Edit   (برای پشتیبان)
Zone    · DNS                    · Edit   (فقط اگر DNS مدیریت می‌شود)
Zone    · Workers Routes         · Edit   (فقط اگر دامنهٔ اختصاصی لازم است)
```

## پشتیبان‌گیری و بازگردانی

راهنمای کامل: [`docs/BACKUP.md`](docs/BACKUP.md)

```bash
# پشتیبان دستی از دیتابیس با Wrangler
npx wrangler d1 export afra-db --remote --output=afra-backup.sql
```

از داخل پنل (**پشتیبان‌گیری**):

- **پشتیبان بدون اسرار** (پیش‌فرض): ستون‌های اعتبارنامه حذف می‌شوند — برای انتقال پیکربندی مناسب است.
- **پشتیبان کامل** (فقط مدیر ارشد): شامل اسرار؛ برای بازگردانی کامل کاربران لازم است.
- **رمزنگاری** با عبارت عبور (AES-256-GCM + PBKDF2) — بدون عبارت عبور بازگردانی ممکن نیست.
- بازگردانی به‌صورت **غیرمخرب** (upsert) انجام می‌شود؛ حالت پاک‌سازی اختیاری و صریح است.

## ارتقا و بازگشت

راهنمای کامل: [`docs/UPGRADE.md`](docs/UPGRADE.md)

```bash
git pull
npm install
npm run typecheck && npm test        # اطمینان از سلامت
npm run db:migrate:remote            # مهاجرت‌های جدید
npm run build && npm run deploy
```

**بازگشت (rollback):** از بخش Deployments در داشبورد Cloudflare نسخهٔ قبلی Worker را فعال کنید
(`npx wrangler rollback`). توجه: مهاجرت‌های دیتابیس به‌صورت خودکار برنمی‌گردند — پیش از ارتقا
پشتیبان بگیرید.

## نکات امنیتی

راهنمای کامل: [`docs/SECURITY.md`](docs/SECURITY.md)

- گذرواژه‌ها هرگز به‌صورت متن ساده ذخیره نمی‌شوند.
- توکن اشتراک، UUID، توکن ربات، راز بک‌اند و توکن Cloudflare **هرگز لاگ نمی‌شوند** (لایهٔ redaction).
- اعتبارنامهٔ Cloudflare فقط سمت سرور استفاده می‌شود و هیچ‌گاه در پاسخ API بازنمی‌گردد.
- بررسی سلامت فقط روی endpointهایی انجام می‌شود که مدیر صریحاً ثبت کرده است — بدون هیچ اسکن عمومی.
- افرا محتوای ترافیک کاربران را بازرسی نمی‌کند؛ تنها متادیتای عملیاتی (حجم مصرفی) ثبت می‌شود و
  این ثبت قابل خاموش‌کردن است.
- گزارش رویدادها همهٔ اقدام‌های مدیریتی را با زمان، منبع، نتیجه و IP ثبت می‌کند.

## محدودیت‌های شناخته‌شده

این موارد صریحاً مستند شده‌اند تا انتظار نادرستی ایجاد نشود:

| مورد | توضیح |
|---|---|
| **Argon2id** | محیط Workers کتابخانهٔ بومی Argon2 ندارد. از PBKDF2-HMAC-SHA512 با ۲۱۰٬۰۰۰ تکرار (پیشنهاد OWASP) استفاده شده. قالب هش نسخه‌دار است تا مهاجرت در آینده ممکن باشد. |
| **Trojan روی لبه** | پروتکل Trojan به SHA-224 نیاز دارد که در WebCrypto موجود نیست؛ بنابراین Trojan فقط برای **Nodeهای بیرونی** پشتیبانی می‌شود (تولید کانفیگ و اشتراک کامل کار می‌کند). |
| **Shadowsocks روی لبه** | رمزنگاری AEAD در Worker پیاده‌سازی نشده؛ فقط برای Nodeهای بیرونی. |
| **UDP** | پراکسی UDP در محیط Workers ممکن نیست؛ فقط TCP پشتیبانی می‌شود. |
| **XHTTP در Clash** | Clash/Mihomo از xhttp پشتیبانی استاندارد ندارد؛ این Nodeها از خروجی Clash حذف و تعدادشان در فایل گزارش می‌شود. |
| **GeoIP / GeoSite** | ارزیابی این قواعد به کلاینت واگذار می‌شود (در کانفیگ تولیدی اعمال می‌گردد)، نه سمت سرور. |
| **Queues** | نیازمند طرح پرداختی Cloudflare است؛ به‌صورت اختیاری و با fallback هم‌زمان پیاده شده. |

│   │   │   ├── db/             # نقشه‌برداری ردیف‌ها
│   │   │   ├── durable/        # RateLimiterDO, HealthCoordinatorDO
│   │   │   ├── modules/        # auth, users, nodes, dns, ... (هر ماژول مستقل)
│   │   │   ├── index.ts        # نقطهٔ ورود + مسیرها
│   │   │   └── scheduled.ts    # وظایف Cron
│   │   ├── test/               # تست‌های واحد و یکپارچگی (اجرا در workerd)
│   │   └── wrangler.jsonc
│   ├── edge/                   # Worker لبه: اشتراک + VLESS over WebSocket
│   └── web/                    # SPA فارسی RTL (React + Vite + Tailwind)
├── packages/
│   └── shared/                 # منطق خالص مشترک + اسکیماهای Zod
├── docs/                       # مستندات فارسی
└── .env.example

## تست‌ها

تست‌ها در **محیط واقعی Workers** (`workerd` از طریق Miniflare) با دیتابیس D1 محلی اجرا می‌شوند —
نه با mock.

```bash
npm test
```

پوشش فعلی: **۸۸ تست** در ۵ فایل

| فایل | موضوع |
|---|---|
| `shared-logic.test.ts` | واحدهای حجم، قالب نام، توازن بار، مسیریابی، CIDR، adapterهای پروتکل، تولید اشتراک |
| `crypto.test.ts` | هش گذرواژه، رمزنگاری AES-GCM، پشتیبان رمزنگاری‌شده، TOTP، مقایسهٔ زمان‌ثابت |
| `auth.test.ts` | راه‌اندازی، ورود، CSRF، brute-force، تغییر گذرواژه، TOTP، بازیابی |
| `users.test.ts` | چرخهٔ کامل کاربر، تحویل اشتراک در سه فرمت، انقضا/اتمام حجم، عملیات گروهی |
| `api.test.ts` | سرورها، RBAC، مسیریابی، DNS، زنجیره، بک‌اند، Cloudflare، تلگرام، پشتیبان، تحلیل‌ها |

```bash
npm run typecheck   # بررسی تایپ همهٔ بسته‌ها
npm run lint        # ESLint
npm run format      # Prettier
```
