# امنیت در پنل افرا

این سند مدل امنیتی افرا را توضیح می‌دهد: چه چیزی چگونه محافظت می‌شود، چه چیزی هرگز ذخیره یا
لاگ نمی‌شود، و چه مسئولیت‌هایی بر عهدهٔ مدیر است.

---

## ۱. احراز هویت مدیر

| مورد | پیاده‌سازی |
|---|---|
| هش گذرواژه | PBKDF2-HMAC-SHA512 با ۲۱۰٬۰۰۰ تکرار و نمک تصادفی ۱۲۸ بیتی (پیشنهاد OWASP ۲۰۲۳) |
| قالب ذخیره | `$afra$pbkdf2-sha512$<iterations>$<salt>$<hash>` — نسخه‌دار برای مهاجرت آینده |
| نشست | توکن تصادفی ۲۵۶ بیتی؛ فقط **SHA-256 توکن** در دیتابیس ذخیره می‌شود |
| کوکی | `HttpOnly; Secure; SameSite=Strict` + انقضای قابل‌تنظیم |
| CSRF | double-submit با راز سمت سرور که در نشست ذخیره و با مقایسهٔ زمان‌ثابت بررسی می‌شود |
| دومرحله‌ای | TOTP (RFC 6238) با پنجرهٔ ±۱ گام؛ کلید با AES-256-GCM رمزنگاری‌شده |
| بازیابی | کد یک‌بارمصرف خوانا (XXXX-XXXX-XXXX-XXXX)؛ فقط hash آن ذخیره و پس از استفاده باطل می‌شود |
| brute-force | محدودسازی نرخ با Durable Object + قفل موقت پس از چند تلاش ناموفق |

### چرا PBKDF2 و نه Argon2id؟

محیط اجرای Cloudflare Workers کتابخانهٔ بومی Argon2 ندارد و افزودن WASM برای هر درخواست هزینهٔ
CPU و حجم باندل ایجاد می‌کند. PBKDF2-HMAC-SHA512 با ۲۱۰٬۰۰۰ تکرار مقدار پیشنهادی OWASP است و روی
WebCrypto بومی اجرا می‌شود. اگر در آینده Argon2 در Workers در دسترس قرار گیرد، قالب نسخه‌دار هش
امکان مهاجرت بدون قطعی را فراهم می‌کند.

## ۲. مجوزها (RBAC)

سه نقش پیش‌فرض و ۲۵ مجوز دانه‌ای:

| نقش | دسترسی |
|---|---|
| `super_admin` | همهٔ مجوزها + مدیریت مدیران + پشتیبان با اسرار + بازگردانی |
| `admin` | همهٔ مجوزها به‌جز مدیریت مدیران |
| `read_only` | فقط مجوزهای `*.read` |

هر route سمت سرور با `requirePermission(...)` محافظت می‌شود. اعتماد به فرانت‌اند هرگز کافی نیست.

---

## ۳. محافظت از اسرار

### رمزنگاری at rest

این مقادیر با **AES-256-GCM** و کلید مشتق‌شده از `AFRA_SECRET_KEY` رمزنگاری می‌شوند:

- کلید TOTP مدیران
- توکن ربات تلگرام و راز webhook
- توکن Cloudflare (اگر از تنظیمات ذخیره شود)
- راز احراز هویت بک‌اندها

### هرگز در لاگ نیاید

لایهٔ لاگ‌گیری یک فهرست redaction دارد و این کلیدها را در هر سطح تودرتو با `[redacted]` جایگزین
می‌کند: گذرواژه، توکن، راز، UUID اعتبارنامه، گذرواژه‌های Trojan/Shadowsocks، TOTP، کد بازیابی،
توکن اشتراک، هدرهای Authorization و Cookie.

توکن اشتراک یک **اعتبارنامه** است: در لاگ‌ها mask می‌شود، پاسخ آن `no-store` است و در گزارش
رویدادها فقط شناسهٔ منبع ثبت می‌گردد.

### هرگز به فرانت‌اند نرود

- توکن Cloudflare و راز بک‌اند هرگز در پاسخ API بازگردانده نمی‌شوند؛ فقط «وجود» آن‌ها گزارش می‌شود.
- هیچ کلید API در جاوااسکریپت سمت کلاینت قرار ندارد.

---

## ۴. امنیت شبکه و HTTP

- **CSP** محدود: `default-src 'self'`، بدون اسکریپت inline، بدون `frame-ancestors`
- `X-Frame-Options: DENY`، `X-Content-Type-Options: nosniff`، `Referrer-Policy`، `Permissions-Policy`
- **CORS** محدود به دامنهٔ پنل و (در حالت توسعه) localhost
- محدودیت حجم بدنهٔ درخواست (۵۱۲ کیلوبایت)
- اعتبارسنجی **Zod** روی همهٔ ورودی‌ها (بدنه، query، مسیر) — ورودی نامعتبر با پیام فارسی رد می‌شود
- کوئری‌های دیتابیس همیشه پارامتریزه (ضد SQL injection)
- خروجی HTML در ربات تلگرام با `escapeHtml` پاک‌سازی می‌شود

---

## ۵. مسئولیت‌های مدیر

افرا امنیت را فراهم می‌کند، اما این موارد بر عهدهٔ شماست:

1. **`AFRA_SECRET_KEY` را امن نگه دارید.** اگر گم شود، اسرار ذخیره‌شده قابل بازیابی نیستند.
2. از **توکن scoped** Cloudflare با کمترین مجوز استفاده کنید، نه Global API Key.
3. گذرواژهٔ مدیر قوی انتخاب کنید و TOTP را فعال نمایید.
4. کد بازیابی را در جای امنی (مدیر گذرواژه) ذخیره کنید.
5. پنل را فقط روی **HTTPS** در دسترس قرار دهید (پیش‌فرض Workers).
6. به‌صورت دوره‌ای گزارش رویدادها را مرور کنید.

---

## ۶. حریم خصوصی

- افرا **محتوای ترافیک** کاربران را بازرسی نمی‌کند.
- تنها متادیتای عملیاتی (حجم مصرفی، زمان آخرین فعالیت) ثبت می‌شود و ثبت ترافیک از تنظیمات
  قابل خاموش‌کردن است.
- هیچ داده‌ای به سرویس شخص ثالث ارسال نمی‌شود؛ همه‌چیز روی حساب Cloudflare خود شما می‌ماند.

---

## ۷. شبکهٔ مسئولانه

- بررسی سلامت فقط روی endpointهای **پیکربندی‌شده توسط مدیر** انجام می‌شود.
- هیچ اسکن عمومی، برداشت اعتبارنامه، یا حمله به زیرساخت دیگران پیاده‌سازی نشده است.
- endpoint لبه فقط UUIDهای موجود در allowlist را می‌پذیرد.
